BulkSMSPlans IVR Webhook Integration

This document explains how BulkSMSPlans should send IVR call events to Brickly CRM for Omaxe. The CRM will receive call details, match or create leads, save call logs, and attach call recordings.

Environment Production
Method POST JSON
Authentication Header Token

Webhook Endpoint

https://omaxe.bihtech.in/api/webhooks/bulksmsplans-ivr

Required Method

POST

Required Content Type

application/json

Authentication

The token must be sent in a request header. Query string tokens are not accepted.

Preferred Header

X-IVR-Token: PASTE_TOKEN_HERE

Alternative Header

Authorization: Bearer PASTE_TOKEN_HERE
Do not send the token like this: ?token=PASTE_TOKEN_HERE. It will be rejected.

Sample Request Payload

Please send call data as JSON. These field names are supported by the CRM.

{
  "type": "ivr",
  "id": "1654557",
  "ivr_number": "7971900088",
  "receiver_number": "917082439354",
  "agent_number": "9713077701",
  "group": "Omaxe Lincoln",
  "status": "ANSWER",
  "call_start_time": "2026-06-24 16:11:42",
  "call_end_time": "2026-06-24 16:12:43",
  "call_duration": 61,
  "recording": "https://example.com/recording.wav"
}

Field Mapping

  • id is used as the unique call ID. Duplicate call IDs will not create duplicate call logs.
  • receiver_number is treated as the customer phone number.
  • agent_number is matched with CRM user phone number.
  • status should contain call result such as answered, missed, busy, no-answer, or similar values.
  • recording should contain the call recording URL when available.
  • call_duration should be sent in seconds.

Expected Responses

Success

{
  "success": true,
  "status": "success",
  "message": "Webhook processed successfully."
}

Invalid Token

{
  "success": false,
  "message": "Unauthorized: invalid token."
}

If this response is received, the request reached Brickly CRM, but the token was missing or did not match.

Current Issue To Check

The CRM is receiving webhook hits, but recent hits are failing with Unauthorized: missing or invalid webhook token. This means the endpoint is reachable, but the token header is not matching.

Please verify from BulkSMSPlans side

  • The exact webhook URL is being used.
  • The request method is POST.
  • The payload is JSON.
  • The token is sent in X-IVR-Token or Authorization: Bearer.
  • The token value has no extra spaces before or after it.
  • The token is not being sent in query string.

Information Requested From Vendor

Please share one latest failed or test webhook request with:

  • Request URL
  • Request method
  • All request headers, especially token header
  • JSON payload
  • Response status code
  • Response body returned by CRM
  • Timestamp of request
